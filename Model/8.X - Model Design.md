# Anomaly Detection: Key Findings from the Literature

## Model Candidates & Selection Rationale

The literature reveals a strong consensus on several model families for financial anomaly detection:

### Ensemble Methods (Dominant Choice)
- **LightGBM** consistently emerges as a top performer, achieving **0.981 ROC-AUC** and **0.902 F1-score** with only 0.58ms latency (Shaha & Gavekar, 2025)
- **XGBoost** demonstrates near-perfect performance with **0.9998 ROC-AUC** on synthetic data (Islam et al., 2026)
- **Random Forest** provides strong precision (0.90) and good interpretability (Scrivano, 2026)
- **Rationale**: Ensemble methods balance predictive accuracy with interpretability, handle class imbalance effectively, and offer low-latency inference suitable for real-time deployment

### Deep Learning Approaches
- **Hybrid CNN-LSTM** (ATAD-Net) achieved **98.65% accuracy** with 8.2ms latency (Abd-Ellatif et al., 2025)
- **Graph Neural Networks** uniquely detect fraud rings invisible to transaction-level classifiers, achieving recall of 0.89 vs 0.78 for Random Forest (Oliveira, 2026)
- **LSTM** with reinforcement learning achieved **0.549 fraud recall** vs 0.226 for GBT (Papanastassiou et al., 2026)
- **Rationale**: Deep models excel at capturing complex temporal and relational patterns but require more computational resources

### Hybrid Architectures
- **Hybrid routing** with adaptive regression reduces inference latency by up to **55%** while preserving fraud recall (Ahmed et al., 2025)
- **XGBoost + DNN ensemble** achieved F1-score of **0.74** with 0.35ms inference time (Luong & Xie, 2026)
- **Mixture-of-Experts** achieved **96.5% recall** with <1.6% false positives (Islam et al., 2025)

## Performance Targets / Success Metrics

### Primary Metrics for Imbalanced Data
| Metric | Priority | Rationale |
|--------|----------|-----------|
| **Recall** | Highest | Missing fraud (FN) carries far heavier cost than false alarms |
| **F1-Score** | High | Balances precision and recall for imbalanced classes |
| **ROC-AUC** | High | Threshold-agnostic measure of discriminative ability |
| **PR-AUC** | High | More informative than ROC-AUC for highly imbalanced data |

### Key Performance Benchmarks
- **Top-tier performance**: 95-99% recall with <5% false positive rate (multiple studies)
- **Real-time requirement**: <10-100ms inference latency for transaction authorization (Ahmed et al., 2025; Abd-Ellatif et al., 2025)
- **Cost-sensitive optimization**: Minimum expected cost `C = c_fp × FP + c_fn × FN` with `c_fn >> c_fp` (Karthikeyan et al., 2026)

### Critical Insight
> "Accuracy is misleading for imbalanced data; a model could achieve 99% accuracy by simply predicting the majority class" (Altalhan et al., 2025)

## Feature Engineering & Thresholds

### Behavioral Features (Most Predictive)
**Source**: Heirene et al. (2026), Shaha & Gavekar (2025), Islam et al. (2025)

- **Transaction frequency** and **velocity** (number per time window)
- **User interaction time** and **navigation patterns**
- **Device/location consistency** scores
- **Behavioral volatility** and **hesitation index**
- **Trust-weighted embeddings** combining long-term and short-term behavior

### Time-Based Features
- **Hour of day** and **day of week** - fraud peaks late-night and weekends (Luong & Xie, 2026)
- **Transaction recency** and **temporal patterns**
- **Rolling window statistics** (mean, variance, trend)

### Threshold Optimization

**Key Finding** (Karthikeyan et al., 2026):
- Fixed threshold at 0.5 underperforms significantly in imbalanced fraud detection
- Cost-sensitive threshold optimization: `τ* = argmin C(τ)` where `C(τ) = C_FN·FN(τ) + C_FP·FP(τ)`
- Example: Model achieved **98.6% recall** with optimized threshold vs **92.4%** with fixed 0.5 threshold

## Cold-Start Hypothesis

### The Challenge
> "Users with limited transaction history are difficult to profile for anomaly detection" (multiple sources)

### Key Strategies from Literature

**1. Behavioral Biometrics** (Islam et al., 2025)
- Dynamic trust-weighted embeddings can identify users **after 14 seconds** of interaction
- Achieves **97.6% user identification accuracy** using interaction patterns

**2. Synthetic Data Generation**
- **GANs** generate synthetic samples to address data scarcity (Chen & Lin, 2025)
- **SMOTE** and **ADASYN** create synthetic minority samples for initial modeling
- **LLM-based augmentation** (PAnDA) generates cold-start user data with **15-37% performance gains** (Du et al., 2025)

**3. Privacy-Preserving Approaches**
- **Federated learning** enables cross-institutional model training without sharing raw data (Owusu-Mensah et al., 2026)
- **Synthetic data generation** enables privacy-preserving development and testing (Qawasmeh & AlQahtani, 2025)

**4. Uncertainty-Based Fallback**
- Flag low-confidence decisions for user review (Jayaprakashnarayan et al., 2026)
- Adaptive buffer retains drifted samples for cold-start retraining (Prashanth et al., 2025)

**Hypothesis from Literature**: Cold-start can be addressed through:
- **Hybrid approach**: Initially use behavioral biometrics + rule-based baselines
- **Rapid learning**: Update user profiles within 14-30 seconds of interaction
- **Synthetic augmentation**: Generate plausible initial profiles from minimal data

## Concept Drift & Assumptions

### Core Finding
> "Non-stationarity is the norm in financial data, not the exception" (Cabral et al., 2026)

### Drift Types Identified
| Type | Description | Detection Method |
|------|-------------|------------------|
| **Sudden** | Abrupt change (e.g., pandemic) | DDM, Page-Hinkley |
| **Gradual** | Progressive change over time | ADWIN, EDDM |
| **Recurrent** | Seasonal patterns recurring | Hybrid approaches |
| **Incremental** | Slow, continuous shift | EWMA, sliding window |

### Key Assumptions in Literature

**1. Static Models Fail** (Chikoore et al., 2026)
- Traditional models degrade within **12-18 months** of deployment
- Retraining alone is insufficient; adaptive fusion achieves **95% accuracy** vs 77% for static

**2. Drift Detection is Essential** (Al Lawati et al., 2025)
- **Dual detection** (EDDM + ADWIN) captures both gradual and abrupt changes
- Achieved **100% drift detection rate** with 100% accuracy on real datasets

**3. Adaptive Frameworks Maintain Performance**

| Method | Finding |
|--------|---------|
| Sliding-window retraining | Up to **5pp AUC improvement** over static (Silvestre et al., 2026) |
| Adaptive SHAP | Maintains explanation stability (cosine ≈ 0.995) under drift (John, 2026) |
| Adaptive buffering | Improves accuracy under abrupt and recurring drifts (Prashanth et al., 2025) |
| Batch-normalization refresh | Safe default for spending pattern shifts (Wu et al., 2026) |

**4. Detection is Not Enough** (Moury, 2026)
- Out-of-time validation (OR=2.83) is a strong predictor of reliable performance
- Calibration reporting (only 34.7% of studies) remains underdeveloped

### Design Implications for Odin

1. **Implement drift detection** (ADWIN or EDDM) as a system-level component
2. **Use hybrid adaptation**: incremental updates + periodic batch retraining
3. **Maintain out-of-time validation** for all algorithmic modules
4. **Monitor calibration** continuously, not just accuracy
5. **Assume concept drift** rather than hoping models stay valid
6. **Design for 30-day data windows** - longer windows don't improve performance (Heirene et al., 2026)

## 4. Feature Selection & Rationale

### Methods for Feature Selection

| Method | Application | Evidence |
|--------|-------------|----------|
| **SHAP-Based Selection** | Identify top features from black-box model; reduce from 86 to 10 features | Schwartz et al. (2024): 88.5% reduction, comparable performance |
| **Correlation Analysis** | Remove correlated lower-ranked features | Schwartz et al. (2024): 0.4% F1 improvement |
| **Physics-Based Features** | Domain-specific feature extraction (82 features initially) | Lien & Rajasekharan (2024): 7-12 features sufficient for 86% accuracy |
| **Temporal Feature Encoding** | Learnable transformations for time features | Chen et al. (2025): LeTE outperforms fixed encodings |

### Critical Insights on Feature Selection

**1. Behavioral features dominate monetary features**
Hopfgartner et al. (2024) found that behavioral variables (self-exclusions, frequent in-session depositing, account depletion) significantly improved model fit (χ²=145.5, p<0.001), while monetary variables did not. Simple total deposits performed near random (AUC ≈ 0.5).

**2. Missingness is predictive**
Chen et al. (2024) found missingness indicators (especially Missing(Attr27)) were highly predictive—more so than many financial ratios—and should be treated as signals rather than noise to be imputed away.

**3. Multi-modal data integration matters**
Yachamaneni et al. (2025) found temporal encoding contributed the largest performance gain (4.2% AUC); web activity features contributed 3.8% AUC when removed.

**4. Feature importance varies by context**
Li & Chen (2025) identified that transaction amount and location are most critical for fraud detection in payment streams, while education level and digital access were top predictors for poverty-based eligibility (Sahraoui & Zari, 2025).

## 6. Concept Drift & Assumptions

### What the Literature Says About Concept Drift

**1. Prevalence and Impact**
> "91% of ML models experience performance decay in production, sometimes within days." — Hasan et al. (2025)

> "Undetected drift leads to an average model accuracy degradation of 31.7%, with healthcare applications seeing up to 52% degradation in the first year." — Mannapur (2025)

**2. Drift Types Most Relevant**

| Drift Type | Relevance | Key Finding |
|------------|-----------|-------------|
| **Concept Drift** | User spending patterns change over time (new jobs, life events) | Affects 82.4% of production quality prediction models |
| **Covariate Drift** | Income, expense patterns shift | Quantile transformation reduced KS statistic from 0.0559 to 0.0072 |
| **Seasonal Drift** | Predictable periodic changes (holidays, pay cycles) | Requires seasonal decomposition to distinguish from anomalies |

**3. Detection Methods**

| Method | Description | Performance |
|--------|-------------|-------------|
| **KS Test** | Kolmogorov-Smirnov compares distributions | Identified 91.3% of significant changes within 18ms |
| **ADWIN** | Adaptive windowing for streaming data | Handles gradual concept drift effectively |
| **DDM** | Drift Detection Method based on error rates | Effective for abrupt drift scenarios |
| **Hoeffding Bounds** | Time-uniform confidence intervals | Provides statistical false alarm guarantees |

**4. Mitigation Strategies**

| Strategy | Effectiveness | Source |
|----------|---------------|--------|
| **Adaptive Retraining** | Improves accuracy by up to 42.8% in dynamic environments | Mannapur (2025) |
| **Model Reuse** | Pool ICM reduced retraining events by 94% with <3% accuracy loss | Eliades & Papadopoulos (2025) |
| **Severity-Aware Updates** | Avoids full retraining for minor drift; saves computational resources | Shakhovska & Pukach (2025) |
| **Batch Training** | Outperforms ignoring drift; robust performance across diverse streams | Pereira & Da Silva (2025) |

### Key Assumptions Documented

**Assumption 1: Drift Will Occur**
Most literature assumes that **all production ML models will face concept drift**. The question is not *if* but *when* and *how severe*.

**Assumption 2: Drift Patterns Are Recurrent**
> "Recurrent concept drift, where past data distributions reappear, is common. Pool ICM explicitly detects recurrence and reuses suitable models." — Eliades & Papadopoulos (2025)

**Assumption 3: Data Drift ≠ Model Drift**
The distinction matters:
- **Data drift**: Input distribution changes (covariate shift) — can be addressed with quantile transformation
- **Concept drift**: Relationship between inputs and outputs changes — requires model retraining

**Assumption 4: Statistical Tests Detect Drift**
Jensen-Shannon Divergence, KS tests, and Wasserstein distance are widely used, but **pooled analysis can mask subgroup-level drift**.

### Critical Insight
> "Subgroup-level analysis can reveal drift masked by pooled aggregation, as seen in housing data where 44 of 45 areas showed significant drift despite overall no drift." — Shakhovska & Pukach (2025)

# Anomaly Detection in Personal Finance Systems: Literature Synthesis

Based on the compiled research summaries (Papers 1-32), here is a comprehensive synthesis of what the literature establishes regarding anomaly detection for personal finance applications like Odin.

## 1. Model Candidates & Selection Rationale

### Established Approaches

**Prediction-Based Methods (Dominant Paradigm)**
- **LSTM and Autoencoder-based methods** represent nearly 50% of new anomaly detection methods proposed between 2020-2023 (Boniol et al., 2024). These are prime candidates for Odin's core detection engine.
- **Multi-SARIMA** extends traditional SARIMA to incorporate two seasonal periods, achieving the highest true positive rates while maintaining fewer false positives than standard SARIMA (Williams et al., 2023).
- **TimeGAN** demonstrates improvements over other time series GANs (RCGAN, C-RNN-GAN, WaveGAN) for generating realistic sequences that can establish normality baselines (Brophy et al., 2023).

**Distance & Density-Based Methods**
- **Matrix Profile** and **LOF** (Local Outlier Factor) remain foundational for subsequence anomaly detection, though they are being superseded by prediction-based approaches in recent literature (Boniol et al., 2024).
- **NETS** is identified as the most efficient point anomaly method, while **NP** performs best for global subsequence anomalies (Zhang et al., 2023).

**Specialized Approaches**
- **Spectral clustering with genetic algorithm-optimized weights** achieved a Silhouette score of 0.91 for customer segmentation, which can inform baseline behavior for anomaly detection (Hamidi & Haghi, 2024).
- **Ensemble methods** like DataStream Adapt combine error-rate monitoring and statistical divergence (KL) for hybrid drift-aware detection, achieving F1-score of 0.89 (Yashwanth et al., 2023).

### Key Selection Criteria

| Criterion | Evidence | Implication for Odin |
|-----------|----------|---------------------|
| **No single best detector** | "No single anomaly detection method is superior for all datasets" (Boniol et al., 2024; Zhang et al., 2023) | Implement model selection or ensemble approach |
| **Online vs. Batch trade-off** | Online methods can be **10x slower** than simple batch methods when window size is large (Zhang et al., 2023) | Consider hybrid approach: batch for training, online for inference |
| **Algorithmic bias risk** | 48 out of 102 reviewed studies raised concerns about algorithmic bias in AI-driven credit/fraud systems (Kowsar et al., 2023; George et al., 2023) | Prioritize fairness-aware algorithms and regular bias audits |
| **Interpretability requirement** | Lack of explainability identified in 29 studies as a critical barrier to adoption (George et al., 2023) | Use SHAP/LIME or inherently interpretable models where possible |

## 6. Concept Drift & Assumptions

### Types of Concept Drift

| Type | Description | Literature Coverage |
|------|-------------|---------------------|
| **Abrupt** | Sudden distribution change | Most frequently adapted type (Xiang et al., 2023) |
| **Incremental** | Gradual shift over time | Supported by adaptive thresholding (Yashwanth et al., 2023) |
| **Gradual** | Slow, continuous change | DataStream Adapt detects with 64.8 instance delay (Yashwanth et al., 2023) |
| **Recurring** | Repeated patterns | Least addressed; Martin et al. (2023) uses selective memory replay |

### Detection Methods

**Statistical Detection**
- **ADWIN** (Adaptive Windowing) statistical test for change detection (Martin et al., 2023)
- **CUSUM** for abrupt drift: `S_t = max(0, S_{t-1} + (ε_t - ε_0 - δ))` (Yashwanth et al., 2023)
- **Moving average** for gradual drift: `x̄_t = (1/k) Σ_{i=t-k+1}^{t} x_i` (Yashwanth et al., 2023)

**Representation-Based Detection**
- **Embedding cosine distance** between hidden representations over a window (Martin et al., 2023):
  `Drift_rep = (1/k) Σ_{t=k-d}^{k} (1 - (h_t · h_{k-d})/(||h_t|| ||h_{k-d}||))`
- **Hybrid detection** combining error-rate monitoring and statistical divergence (KL) (Yashwanth et al., 2023)

### Adaptation Strategies

**Parameter vs. Structure Updates**
- Parameter updates are more common than structural updates due to faster convergence (Xiang et al., 2023)
- Active detection modes explain drift occurrence and save computing resources (Xiang et al., 2023)

**Continual Learning Approaches**
- **EWC (Elastic Weight Consolidation)** penalizes changes to important weights: `Ω = ½ Σ_i F_i (θ_i - θ_i*)^2` (Martin et al., 2023; Ao & Fayek, 2023)
- **Selective memory replay** with bounded rehearsal buffer and exemplar selection (Martin et al., 2023)
- **MC-SGD** reduced forgetting by nearly 29% compared to joint-task training (Ao & Fayek, 2023)

**Performance Targets Summary:** The literature prioritizes cost-sensitive metrics (WA, PR-AUC, F1) over raw accuracy, recognizing the asymmetric costs of false positives vs. false negatives in anomaly detection.

# 8.C

Based on the provided literature compilation, here is a summary of the key findings, trends, and consensus regarding anomaly detection, specifically focusing on the six requested areas.

### 1. Model Candidates & Selection Rationale

The literature presents a wide array of model candidates for anomaly detection, with no single "best" algorithm. The choice is heavily dependent on the specific data characteristics, operational constraints, and application goals.

- **Dominant Unsupervised & Isolation-Based Models:** **Isolation Forest** is frequently cited as a strong, efficient baseline ([Fariha et al.], [Zhong]). Other robust unsupervised methods include **Local Outlier Factor (LOF)** and **One-Class SVM** ([Bader & Haraty], [Fariha et al.]). These are favored for their ability to operate without labeled data, making them suitable for cold-start scenarios.
- **Deep Learning & Sequence Models:** For sequential spending data, **LSTM, GRU, and autoencoders** are the primary candidates ([Bader & Haraty], [Zhang & Duan], [Yunita et al.]). They excel at capturing temporal dependencies and complex patterns. Studies show LSTM-based hybrids are often descriptively superior ([Yunita et al.]).
- **Ensemble & Hybrid Approaches:** There is a strong consensus that **hybrid models** outperform single algorithms. Combining supervised and unsupervised methods (e.g., XGBoost with Isolation Forest) or deep learning with tree-based models (e.g., **XGB+DNN**) yields higher accuracy and robustness ([Luong & Xie], [Kashif & Naseer], [Compagnino et al.]). **Ensemble methods** like Random Forest are also robust against imbalanced data.
- **Graph-Based & Relational Models:** For detecting complex, coordinated fraud rings, **Graph Neural Networks (GNNs)** and graph-based risk scoring show significant power, contributing up to 40-50% of incremental detection lift ([Holmgren], [Adlermann]). However, they are computationally expensive.
- **Performance vs. Interpretability Trade-off:** There is a recognized trade-off. Deep learning models offer high accuracy but act as "black boxes," whereas tree-based models (e.g., XGBoost, Random Forest) provide better interpretability, which is crucial for regulatory compliance and user trust ([Kalideen], [Compagnino et al.]).

### 2. Performance Targets / Success Metrics

The literature is unanimous in its rejection of simple **accuracy** as a meaningful metric for anomaly detection due to extreme class imbalance.

- **Primary Metrics:** The most recommended and commonly used metrics are **F1-Score**, **Precision**, and **Recall** (or Detection Rate). These provide a balanced view of performance on the minority (anomalous) class ([Kalideen], [Jafarigol et al.]).
- **Threshold-Independent Metrics:** **AUC-ROC** (Area Under the Receiver Operating Characteristic) and **AUC-PR** (Area Under the Precision-Recall Curve) are critical for evaluating the model's inherent ranking ability without a fixed threshold. **AUC-PR** is often considered more informative for highly imbalanced datasets ([Zhang et al.], [Jafarigol et al.]).
- **Specialized Metrics for Sequential Data:** For time-series anomalies, **Range-AUC** and **Volume Under the Surface (VUS)** are proposed as more accurate evaluation measures than point-based metrics, which can inflate performance scores by 27-31% ([Boniol et al.]).
- **Reported Benchmarks:** In the reviewed studies, leading models often achieve high performance, with **F1-scores ranging from 0.74 to 0.93** and **AUC-ROC scores from 0.88 to 0.97**, depending on the dataset and task complexity. For instance, the hybrid XGB+DNN ensemble achieved an F1-score of 0.74 ([Luong & Xie]), while a Temporal-Attention Isolation Forest achieved an F1 of 0.927 ([Huang A. et al.]).

### 3. Feature Engineering & Thresholds

Feature engineering is consistently presented as a critical step for successful anomaly detection.

- **Key Features:** For transaction data, the most influential features are **transaction amount**, **temporal markers** (time of day, day of week), **merchant/identity features**, and **behavioral patterns** (e.g., deviations from a user's average spend, inter-transaction intervals) ([Luong & Xie], [Darwish et al.], [Fariha et al.]). For financial risk, **ROE and ROA** are identified as top indicators ([Zhang & Duan]).
- **Behavioral Profiles:** Many approaches build a **behavioral profile** for each user. Engineered features like "unusual spend," "rapid use," and "spending sprees" are combined with algorithmic outputs to create a composite risk score ([Fariha et al.]).
- **Dynamic Thresholds over Static:** The literature strongly advocates for moving beyond static thresholds. **Dynamic calibration**—using sliding windows, quantile-based updates, or Bayesian changepoint detection—is crucial for reducing false positives (by up to 46.5% in one study) in non-stationary data ([Zhong], [Huang A. et al.]). New methods like **Segmented Confidence Sequences (SCS)** and **Multi-Scale Adaptive Confidence Segments (MACS)** provide statistical guarantees on false alarm rates while adapting to local data changes ([Li & Gautam]).

### 4. Feature Selection & Rationale

Explicit feature selection is often a precursor to effective modeling, particularly with high-dimensional data.

- **Information Value & Causal Importance:** One study proposes a hybrid feature selection combining **Information Value**, Causal Forest importance, **Population Stability Index**, and Stepwise refinement, which improved uplift model performance by 25-30% ([Jiang et al.]). This highlights the importance of selecting both predictive and causally relevant features.
- **Techniques for Dimensionality Reduction:** The **curse of dimensionality** is a major challenge for clustering and distance-based models. Dimensionality reduction techniques like **PCA, t-SNE, UMAP, and variational autoencoders (VAEs)** are suggested to create a more salient feature space for classification and clustering ([Wani], [Nooji et al.]).
- **Interpretability for Justification:** **SHAP (SHapley Additive exPlanations)** is the most frequently cited tool for post-hoc feature importance analysis. It provides transparent, human-readable justifications for model decisions, helping to identify which features (e.g., "Financing Needs," "Credit Amount") are most influential and building user trust ([Hartomo et al.], [Luong & Xie]).

### 5. Cold-Start Hypothesis

The "cold-start" problem—how to make reliable predictions for a new user with no transaction history—is a major focus of research. Several core hypotheses are explored:

- **Generative Data Synthesis:** A strong hypothesis is that using **LLMs** (e.g., GPT-4) or **GANs** to generate synthetic user profiles can effectively bootstrap a system, significantly reducing initial prediction error ([Bachmann et al.], [Lu et al.]). This pre-training can give a model a significant early advantage (e.g., reducing initial RMSE by 25%).
- **Transfer Learning:** The **TechCD** framework demonstrates that a **knowledge graph** can be used to transfer user state information from one domain to another, enabling "zero-shot" profiling without any target-domain interaction data ([Gao et al.]). This hypothesis supports inferring profiles for new users from similar users or external data sources.
- **Collaborative Filtering & Classification:** For new users, **XGBoost classification** based on demographic attributes can be used as a fallback to predict behavior when collaborative filtering fails due to lack of history ([Pritam & Pramod]).
- **Robust Unsupervised Learning:** Algorithms like **Isolation Forest** and **One-Class SVM** are hypothesized to be effective cold-start baselines because they can learn a profile of "normal" behavior solely from the limited data available in the initial session, without requiring labeled anomalies ([Fariha et al.], [Kalideen]).

### 6. Concept Drift & Assumptions

There is a widespread acknowledgment that **non-stationarity is the norm** in financial data, making the assumption of a static data distribution inherently flawed.

- **Drift as a Core Challenge:** "Concept drift"—the change in the relationship between features and the target variable over time—is identified as a fundamental and critical challenge for anomaly detection ([Cabral et al.], [Kalideen]).
- **Common Assumptions & Required Mitigations:** The dominant assumption is that data distributions will change. This necessitates:
    - **Continuous Monitoring & Adaptation:** Predictive models must be continuously monitored and updated. Hybrid adaptation architectures that combine continuous updates with event-driven retraining are recommended ([Cabral et al.]).
    - **Adaptive Buffering:** Using **adaptive buffering**—which retains only drifted batches for training—has been shown to improve accuracy under abrupt and recurring drift compared to fixed-window (FIFO) or no-buffer strategies ([Prashanth et al.]).
    - **Unified Detection Frameworks:** Frameworks like **DataStream Adapt** are proposed to detect and respond to both abrupt and gradual drifts using a hybrid of error-rate monitoring and statistical divergence, coupled with an adaptive threshold controller ([Yashwanth et al.]).
- **Types of Drift:** Studies distinguish between **abrupt** (sudden change), **gradual**, and **recurring** drift, with different detection methods (e.g., CUSUM for abrupt, moving averages for gradual) proving more effective for each type ([Cabral et al.], [Yashwanth et al.]).

### Conclusion

The compiled literature provides a clear, evidence-based framework for designing an anomaly detection system. Key takeaways for your Odin project include:

- **Prioritize hybrid and unsupervised models** like Isolation Forest for cold-start scenarios and ensembles for high accuracy.
- **Reject accuracy as a metric** and focus on F1-score, AUC-PR, and specialized range metrics for time-series data.
- **Engineer behavioral features** (deviation, frequency, temporal) and use **dynamic thresholds** for adaptive performance.
- **Leverage SHAP for feature importance** to justify decisions to users.
- **Treat cold-start as a solvable problem** using synthetic data generation from LLMs or GANs, or transfer learning from similar user profiles.
- **Explicitly plan for concept drift** by designing a system with continuous monitoring, model retraining, and adaptive buffering mechanisms to maintain performance over time.
